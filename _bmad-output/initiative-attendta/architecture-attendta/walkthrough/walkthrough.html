AttendTa architecture spine — team walkthrough

One ASP.NET Core MVC app, one SQL Server database, eight epics built in parallel. This deck walks the 18 decisions (AD-1…AD-18) that keep those epics compatible.

  • Source of truth: _bmad-output/initiative-attendta/architecture-attendta/architecture-attendta.md
  • Cite decisions by ID in stories, PRs and reviews (e.g. “violates AD-4 lock order”). IDs never change.
  • Rationale and history: .memlog.md in the same folder; the long-form companion stays docsss/architecture.md.
  • Editable diagrams: walkthrough/attendta-architecture.drawio (open in draw.io; one page per diagram).
Decided today: retarget to net10.0 LTS (.NET 9 support ends 2026-11-10) · keep AutoMapper 14.0.0 for flat maps only.
2/9

AD-1 · Layered monolith

  • WebApp → Services → Data; Resources is a leaf everyone may read.
  • Controllers call services only; never repositories or DbContext.
  • Services declare interfaces (ICurrentActor, IPrivateFileStore, IPasswordHasher); WebApp implements them.
  • No new projects except the two test projects.
3/9

AD-2 · Who writes what

  • Each table has one writer module; everyone else calls that module's service.
  • Reads across modules go through Data-layer queries and ParticipationFacts — no service dependency.
  • Hooks invert the late epic: e3 and e4 declare IEventCompletionHandler / IAttendanceInvalidationHandler; e6 implements both.
  • Before e6 merges, zero handlers run — correct, since no certificate rows exist yet.
4/9

AD-3 · AD-7 · AD-9 · Anatomy of a use case

  • Every mutation: ExecuteInTransactionAsync → locks → recheck → mutate → audit → commit.
  • Flush (SaveChangesAsync) inside the transaction is fine for identity keys; only the outer scope commits.
  • Failures are DomainException(OutcomeCode); controllers map them to page feedback or JSON.
  • Audit row is written in the same transaction, via IActivityLogWriter, with action codes from AuditActions.
5/9

AD-4 · Lock ladder

  • Always lock downward; primary-key seeks only.
  • Per-participant work locks the owner's users row first, then the event.
  • Event create/edit/publish lock type and venue first so capacity and active checks hold.
  • Queue picks: discover → lock → recheck; if anything moved, roll back with Stale.
6/9

AD-16 · AD-17 · Environments

  • Dev: your own LocalDB AttendTaMVP_Test; secrets via env vars or user-secrets.
  • CI: GitHub Actions + SQL Server 2025 container; integration tests make a fresh AttendTa_IT_<guid> database per class.
  • Demo: one host, Kestrel HTTPS on the hotspot with a phone-trusted certificate, everything offline (Tailwind compiled, Chromium pre-installed).
  • Back up SQL and SetupRoot together.

e1 goes first — the platform baseline

  • Retarget all projects to net10.0; move Microsoft.* and EF Core to 10.0.x together (AD-18).
  • Canonical schema: lookup tables + FKs, RCSI, audit trigger, unique keys, DB-name allow-list; fix seed-event-types.sql descriptions (AD-10).

  • Audit writer, pager, DomainException, ICurrentActor, compiled Tailwind shell, both test projects, CI workflow (AD-7, AD-9, AD-13, AD-14, AD-17).
  • Remove Hangfire, BulkExtensions, System.Drawing, ZXing; suppress NU1903 on AutoMapper only (AD-18).
