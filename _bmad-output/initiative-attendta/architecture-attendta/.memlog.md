- (decision) AD-1 paradigm [ADOPTED]: layered MVC monolith, WebApp -> Services -> Data, Resources shared by all; use cases are transaction-script service methods; Data never references Services types. Binds all epics. Prevents a second app/domain project or controllers reaching repositories.
- (decision) AD-2 module ownership: each table has exactly one writing module (users/account_requests: platform-access, role+is_active: administration; members: created by platform-access approval, edited by master-data, membership status by administration; event_types/venues: master-data; events: events-registration except check_in_open toggled by check-in; registrations: events-registration only; attendance: check-in only; certificates: certificates only; activity_logs: append via shared writer). Other modules call the owner's service interface; never write another module's table via its own repository. Prevents two owners of one entity.
- (decision) AD-3 unit of work [ASSUMPTION on API names]: repositories never call SaveChanges and never begin transactions; each mutating use case runs inside IUnitOfWork.ExecuteInTransactionAsync(work, ct) which opens one SQL transaction (READ COMMITTED), runs work, SaveChangesAsync once, commits; nested calls join the ambient transaction and never commit. Cross-module services (cancellation, review seeding) require an ambient transaction and throw if none. Existing master-data repo SaveChanges calls migrate in platform-access. Prevents half-committed multi-record mutations and audit outside the change commit.
- (decision) AD-4 lock protocol [ASSUMPTION on exact SQL]: serialization uses SQL Server row locks via repository Lock*Async methods issuing SELECT ... WITH (UPDLOCK, HOLDLOCK, ROWLOCK); global acquisition order: app lock 'attendta:last-admin' (sp_getapplock, Exclusive, Transaction) -> account_requests -> users (ascending id) -> event_types -> venues -> events (ascending id) -> registrations/attendance/certificates. Participation rows are written only while holding their event lock. Per-participant mutations (approve, promote, member/admin cancel, check-in) lock the owner's users row then the event. Discover-then-lock: after acquiring locks, recheck; if the candidate/priority changed, roll back and return Stale. No process-local locks; no blind retry after unknown commit. Prevents deadlocks from inverted orders and overbooking/duplicate issuance.
- (decision) AD-5 canonical participation facts: one Data-layer definition each, reused by every module: Eligible Participant = users.is_active AND member membership status active; Valid Attendance = attendance row exists AND invalidated_at IS NULL; Seat = registration in confirmed status; Waitlist priority = reviewed_at ASC, registration_id ASC; Event Start Cutoff = now >= events.starts_at; Signup open = published AND now < registration_deadline. Lives in ASI.Basecode.Data/Queries/ParticipationFacts.cs; created by events-registration, Valid Attendance owned by check-in. Prevents divergent eligibility/validity definitions across cancel, deactivation, issuance, reports.
- (decision) AD-6 participation cancellation: events-registration owns IRegistrationCancellationService.CancelAsync(selection, cause, reason, ct); the only code path that moves a registration to cancelled; clears qr_token, sets reason/actor/time, writes one registration.cancelled audit entry per row, never promotes; joins caller transaction and assumes caller holds AD-4 locks. Callers: event cancel, admin cancel, member cancel, decline, administration deactivation. Prevents a second cancellation implementation in administration.
- (decision) AD-7 audit writer: IActivityLogWriter.Append(AuditEntry) adds a row to the current DbContext (no SaveChanges); action codes are constants in ASI.Basecode.Resources/Constants/AuditActions.cs named '<entity>.<past_verb>' (e.g. registration.approved); entity_type = table name; old/new values serialized with System.Text.Json from explicit field-subset records, never entities; denylist password_hash, qr_token, file_path, image_path, tokens; actor and occurred_at come from current actor and TimeProvider. Append-only enforced by INSTEAD OF UPDATE/DELETE trigger in schema plus runtime SQL role SELECT/INSERT on demo host. Prevents divergent action vocabularies and secrets in logs.
- (decision) AD-8 identity [ASSUMPTION on names]: standard ASP.NET Core cookie auth (Data Protection ticket; remove JwtBearer, CustomJwtDataFormat, /api/token); claims NameIdentifier = users.user_id (int) and Role = role code; 8h non-persistent, no sliding; OnValidatePrincipal reloads users row each request and rejects inactive or role-changed sessions; services read the actor from ICurrentActor (Services interface, WebApp adapter) and never accept actor ids or roles from request models; authorization via named policies Management (officer, administrator) and Administrator, plus ownership checks in use cases; role codes are constants. Prevents actor spoofing and role-string drift.
- (decision) AD-9 outcomes [ASSUMPTION]: services signal business failures by throwing DomainException(OutcomeCode, message, field?) with OutcomeCode in {Invalid, Forbidden, NotFound, Stale, Duplicate, CapacityUnavailable, CutoffPassed, FileFailure}; replaces InvalidDataException; Data layer translates unique-index violations (SQL 2601/2627) to Duplicate; controllers map codes to ModelState/TempData for pages and to HTTP status + JSON {outcome, message} for scanner/AJAX; never expose SQL text, stack traces, tokens. Prevents per-epic error shapes.
- (decision) AD-10 lookup states: every enumerated state is a seeded lookup table (id tinyint explicit, code varchar unique, label) referenced by FK; C# enums in ASI.Basecode.Data/Models/Lookups with explicit numeric values equal to seeded ids; never infer ids from order; lookups not editable. Canonical schema database/attendta-mvp-schema.sql is the single source; platform-access writes all ten tables + lookups up front; later schema changes edit that script and the DbContext fluent mapping in the same PR; no EF migrations; fluent mapping only in AsiBasecodeDbContext. Prevents per-epic string states and schema forks.
- (decision) AD-11 time: inject TimeProvider (System); every guard compares TimeProvider.GetUtcNow() against stored UTC datetime2(3); no DateTime.Now/UtcNow in Services; Asia/Manila conversion only at WebApp display via one shared formatter that appends the zone label. Prevents mixed clocks and untestable cutoffs.
- (decision) AD-12 private file store: one IPrivateFileStore (Services interface, WebApp/Storage impl generalizing VenueImageStorage) rooted at Common:SetupRoot with areas uploads/venues, uploads/events, certificates, temporary; images JPEG/PNG by magic bytes, <= 2 MiB, generated names, CreateNew; write file first, commit DB, then delete the replaced file; on failure delete the new file; SQL holds relative paths only; downloads stream through authorized controller actions, never static middleware. Prevents competing roots and orphan/overwrite bugs.
- (decision) AD-13 paging: one PageRequest/PagedResult<T> in Services/ServiceModels + one _Pager partial; size fixed 25; order with unique-id tiebreak in the SQL query; filter and authorize before Count; page normalization (missing/invalid -> 1, beyond -> last); built by platform-access. Prevents per-screen paging semantics.
- (decision) AD-14 UI shell: compiled Tailwind via pinned @tailwindcss/cli into wwwroot/css/app.css; Bootstrap and all runtime CDNs removed (toastr/jQuery vendored or replaced locally); role-routed shared layouts from ux DESIGN.md tokens; feedback through TempData SuccessMessage/ErrorMessage [ADOPTED]; dynamic class names safelisted in source.
